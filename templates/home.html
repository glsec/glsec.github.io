Find the security problems in your .gitlab-ci.yml before a runner does.

glsec is a static security linter for GitLab CI/CD pipelines. It catches mutable images and includes, script injection through branch names and commit messages, leaked secrets and unprotected deployments. It runs offline as a single binary and never executes your pipeline.

Every finding names the rule, the line and the job. Each rule has a page with the risk, what is flagged and a safe alternative, for example GL001 and GL011.

Install

GitLab CI/CD component

include:
  - component: gitlab.com/glsec-io/glsec/glsec@{{.Component}}

From the CI/CD Catalog. A second component reports findings in the merge request's Code Quality widget.

Package managers

brew install glsec/tap/glsec
aqua g -i glsec/glsec && aqua i
mise use github:glsec/glsec
pipx install glsec

Homebrew, aqua, mise and PyPI (also uvx glsec). The Homebrew tap and aqua install a release only after its provenance check passes; the PyPI wheels carry the release binary after the same check.

Docker

docker run --rm -v "$PWD:/src:ro" -w /src \
  ghcr.io/glsec/glsec:{{.Version}}

Signed with cosign, with SLSA provenance and an SBOM.

Binary

curl -sSLO https://github.com/glsec/glsec/releases/download/v{{.Version}}/glsec_{{.Version}}_linux_amd64.tar.gz
tar xzf glsec_{{.Version}}_linux_amd64.tar.gz

Linux, macOS and Windows on the release page. Or go install github.com/glsec/glsec/cmd/glsec@v{{.Version}}.

Claude Code plugin

/plugin marketplace add glsec/glsec
/plugin install glsec@glsec

Adds /glsec:scan, which scans the project and has Claude explain and fix each finding, and a hook that scans a .gitlab-ci.yml or .gitlab/*.yml file after Claude edits it. Without a glsec on your PATH it downloads the release binary and checks it against checksums.txt and, with cosign or the GitHub CLI installed, its signed provenance. Linux and macOS; the edit hook needs jq. Details in the README.

Also available as a pre-commit hook and a MegaLinter plugin. Output formats: text, table, JSON, SARIF, GitLab Code Quality and JUnit, with an example of each. See the README for every option, and Verifying a release to check a download before you run it.
