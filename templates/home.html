Find the security problems in your .gitlab-ci.yml before a runner does.

glsec is a static security linter for GitLab CI/CD pipelines. {{.RuleCount}} rules cover mutable images and includes, script injection through branch names and commit messages, leaked secrets, unprotected deployments and more. It runs offline as a single binary and never executes your pipeline.

Install Browse the rules

What a finding looks like

$ glsec .gitlab-ci.yml
{{.Sample}}

Every finding names the rule, the line and the job. Each rule has a page with the risk, what is flagged and a safe alternative, for example GL001 and GL011.

Install

GitLab CI/CD component

include:
  - component: gitlab.com/glsec-io/glsec/glsec@{{.Component}}

From the CI/CD Catalog. A second component reports findings in the merge request's Code Quality widget.

Docker

docker run --rm -v "$PWD:/src:ro" -w /src \
  ghcr.io/glsec/glsec:{{.Version}}

Signed with cosign, with SLSA provenance and an SBOM.

Binary

curl -sSLO https://github.com/glsec/glsec/releases/download/v{{.Version}}/glsec_{{.Version}}_linux_amd64.tar.gz
tar xzf glsec_{{.Version}}_linux_amd64.tar.gz

Linux, macOS and Windows on the release page. Or go install github.com/glsec/glsec/cmd/glsec@v{{.Version}}.

Also available as a pre-commit hook, a MegaLinter plugin and a Claude Code plugin. Output formats: text, table, JSON, SARIF, GitLab Code Quality and JUnit. See the README for every option, and Verifying a release to check a download before you run it.
